# Matrices

Store structured decision tables here.

Examples:

- topic selection matrix
- stakeholder matrix
- problem-impact-feasibility matrix
- feature prioritization matrix
- risk and governance matrix
- data requirement matrix
- evaluation matrix for mock cases

This folder helps convert research notes into decisions the team can defend during pitching.

## Initial matrix set

After the six member literature reviews are available, create:

- `feature_feasibility_impact_matrix.md`
- `data_requirement_matrix.md`
- `stakeholder_contact_point_matrix.md`
- `stakeholder_ecosystem_matrix.md`
- `risk_governance_matrix.md`
- `roadmap_decision_log.md`

The initial decision matrix set was created from the six analyzed research streams, the integrated Pitch 1 brief, and the dashboard requirement concept. The stakeholder ecosystem matrix was added on 2026-08-22 to make system levels, related organizations, resource actors, and future opportunity space explicit. These are working decision artifacts and should be updated when the team confirms local thresholds, stakeholder ownership, data access, or Phase 0 test parameters.

Every row should include a traceability reference to a member literature review and, where possible, the original source. Use `Evidence`, `Interpretation`, `Assumption`, and `Decision` labels so that the team can distinguish research from design choices.

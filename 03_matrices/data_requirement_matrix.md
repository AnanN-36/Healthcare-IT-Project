# Data Requirement Matrix

**Purpose:** define the minimum data needed for the retrospective dashboard and mock workflow simulator.  
**Rule:** evidence-backed, mock, future, and unresolved fields must remain visibly distinct.  
**Updated:** 2026-08-21

| Data domain | Required fields for Phase 0 | Data status | Quality or governance rule | Evidence / Interpretation / Assumption / Decision | Traceability |
|---|---|---|---|---|---|
| Historical health indicator | indicator_id, metric_name, value, unit, year/period, geography, source_file, locator | Evidence-backed | Preserve original unit and locator; do not infer missing values | Evidence: Mod and My define indicator and source interpretation. **Decision:** Use selected Lancet historical aggregate data. | Mod review; My review |
| Heat or weather context | source_id, variable, value, unit, timestamp, geography, coverage period | Candidate or illustrative | Label historical, current, forecast, and illustrative separately | Evidence: My identifies source classes. **Decision:** Use only if source meaning and licence are clear; otherwise use mock/candidate fields. | My review; June notes |
| Official advisory context | advisory_id, issuing_authority, issue_time, valid_period, wording, source_url/file | Candidate | Do not convert wording into an official threshold without authority confirmation | Evidence: June and My support source-aware warning/action logic. **Decision:** Keep as reference context, not a clinical rule. | My review; June notes |
| Geography | geography_code, geography_name, level, boundary_version | Evidence-backed or mock | State geography level and version; do not combine incomparable units silently | Interpretation: data from different geography levels needs explicit mapping. **Decision:** Choose one consistent demo geography level. | My review; Com review |
| Vulnerable context | cohort_id, age_group, occupation_group, chronic_disease_group, living_alone_group, cooling_access_group | Mock or aggregate | No names, addresses, identifiers, or individual clinical records in Phase 0 | Evidence: Mod defines vulnerable contexts. Assumption: chronic disease, living alone, and cooling access are mock/future unless approved aggregate data exists. | Mod review; Com review |
| Operational signal | signal_id, area, period, indicator_ref, signal_label, rationale, reviewer, review_status | Mock workflow | Use `high-priority operational signal`; do not call it clinical risk | Interpretation: translates evidence into a human-reviewable workflow state. **Decision:** Required simulator object. | Mod review; Belle review |
| Task | task_id, signal_id, task_type, owner_role, assignee_role, priority, due_state, status, created_at | Mock workflow | Task states must be separate from heat-risk states | Evidence: Belle defines task registry; Chris defines handoff ownership. **Decision:** Required simulator object. | Belle review; Chris matrix |
| Handoff and acknowledgement | handoff_id, sender_role, receiver_role, channel, sent_at, acknowledgement_state, acknowledgement_at | Mock workflow | Transmission, receipt, acknowledgement, and action are separate states | Evidence: Chris central finding. **Decision:** First-class fields in prototype. | Chris review; Chris contact matrix |
| Fallback and escalation | fallback_id, trigger_state, fallback_owner, fallback_channel, escalation_state, escalated_at | Mock workflow | Fallback should have an independent failure mode; response window is a test parameter | Evidence: Chris channel strategy. Assumption: no final policy SLA. | Chris review; June notes |
| Audit and provenance | source, source_locator, imported_at, transformed_at, actor, action, comment | Evidence-backed metadata and mock audit | Keep source and actor traceability for every processed record or simulated action | Evidence: My and Com specify provenance/audit. **Decision:** Required for demo trust. | My review; Com review |
| Data quality | quality_flag, missing_reason, stale_flag, conflict_flag, validation_note | Metadata | Missing is not zero; conflicts must be visible; assumptions must be labelled | Evidence: My defines quality rules. **Decision:** Required on data view. | My review |
| Evaluation result | scenario_id, user_role, task_completed, acknowledgement_found, source_found, error_count, ease_rating, comment | Mock evaluation | Measure feasibility/usability, not health outcomes | Evidence: June and Chris evaluation frameworks. | June notes; Chris evaluation |

1. CORE CONCEPT & PROJECT VISION (แนวคิดหลักและวิสัยทัศน์ของโครงการ)
--------------------------------------------------------------------------------
โครงการนี้จัดตั้งขึ้นเพื่อแก้ไขปัญหา "ช่องว่างของข้อมูล" ในระบบสาธารณสุขในปัจจุบัน (Main Systems) 
ซึ่งระบบส่วนใหญ่มักประมวลผลเฉพาะข้อมูลทางคลินิก (Clinical Data) ภายในโรงพยาบาลเป็นหลัก 
แต่ขาดการเชื่อมโยงกับปัจจัยภายนอก (External Factors) ที่ส่งผลกระทบสำคัญต่อสุขภาพของผู้ป่วย 
ดังนั้น วิสัยทัศน์ของโครงการคือการสร้างระบบที่ผสานข้อมูลสุขภาพและข้อมูลสิ่งแวดล้อมเข้าด้วยกันภายใต้:

  - ปัจจัยแวดล้อม (Factors): ปัจจัยกำหนดสุขภาพทางสังคม (Social Determinants of Health) และสภาพทางกายภาพเชิงพื้นที่
  - ภูมิอากาศ (Climate): ปัญหาการเปลี่ยนแปลงสภาพอากาศ เช่น อุณหภูมิ ฝุ่นละออง (PM2.5) ที่ส่งผลต่อโรคทางเดินหายใจ/โรคเรื้อรัง
  - มาตรฐานสุขภาพสากล (Criteria of Global Health): การยกระดับระบบซอฟต์แวร์สุขภาพให้เป็นไปตามเกณฑ์ระดับสากล 
    มีความปลอดภัยสูง และคุ้มครองสิทธิ์ของผู้ป่วยอย่างเคร่งครัด

2. PROJECT SCOPE (ขอบเขตและเป้าหมายเชิงพัฒนาระบบ)
--------------------------------------------------------------------------------
โครงการนี้จะมุ่งเน้นไปที่การสร้างต้นแบบระบบซอฟต์แวร์ (Software Prototype) 
เพื่อพิสูจน์แนวคิดการผสานข้อมูล ไม่ใช่งานวิจัยเชิงทฤษฎี โดยมีขอบเขตสำคัญดังนี้:

  [สิ่งที่อยู่ในขอบเขต (In-Scope)]
  - การออกแบบสถาปัตยกรรมข้อมูล (Data Schema/Architecture) ที่พร้อมเชื่อมโยง HL7 FHIR Standard
  - การจัดทำเวิร์กโฟลว์จำลองของบุคลากรทางการแพทย์ร่วมกับข้อมูลเชิงพื้นที่และภูมิอากาศ
  - การพัฒนาตารางประเมินผลและหลักเกณฑ์การสนับสนุนการตัดสินใจทางคลินิก (Clinical Decision Support)
  - การจำลองกลุ่มข้อมูลเคสผู้ป่วย (Mock Patient Cases) และการพัฒนาหน้าจอ Dashboard ต้นแบบ

  [สิ่งที่อยู่นอกขอบเขต (Out-of-Scope)]
  - การเชื่อมต่อ API จริงกับอุปกรณ์ตรวจวัดสภาพอากาศส่วนบุคคล (Wearables) ในระบบใช้งานระดับขนาดใหญ่ (Production Scale)
  - การรักษาสภาวะทางการแพทย์จริงหรือวิเคราะห์วินิจฉัยโรคทดแทนแพทย์ (ระบบเป็นเพียงผู้สนับสนุนข้อมูลเท่านั้น)

3. PIPELINE RULES & WORKFLOW (กฎเหล็กและกระบวนการทำงานของทีม)
--------------------------------------------------------------------------------
เพื่อควบคุมคุณภาพและรักษาความน่าเชื่อถือของผลงาน สมาชิกทุกคนในทีมและระบบอัตโนมัติ (Codex) 
จะต้องปฏิบัติตาม "กฎและทิศทางการจัดเก็บเวิร์กโฟลว์แบบทีละขั้น" (Research-to-Prototype Pipeline) 
โดยห้ามข้ามขั้นตอนอย่างเด็ดขาด:

  [กฎข้อที่ 1: ขั้นข้อมูลดิบ (00_raw_materials)]
  - ห้ามแก้ไขดัดแปลง (Do Not Edit) ไฟล์ต้นฉบับในโฟลเดอร์นี้เด็ดขาด เพื่อคงสภาพ "ความสามารถในการสืบย้อนกลับ (Traceability)" 
    สำหรับใช้ตรวจสอบแหล่งที่มาของการตัดสินใจในภายหลัง
  - ทุกรายงานทางแพทย์, บันทึกการประชุม, หรือทฤษฎีสิ่งแวดล้อมที่รวบรวมได้ จะต้องจัดเก็บในสภาพเดิมเท่านั้น

  [กฎข้อที่ 2: ขั้นแผนภาพขั้นตอนการทำงาน (01_general_workflow)]
  - ต้องวาดแผนภูมิขั้นตอนการทำงานทั้ง "สถานะปัจจุบัน (Current-state)" และ "สถานะในอนาคต (Future-state)" 
    เพื่อระบุจุดติดขัด (Bottlenecks) ของระบบก่อนเริ่มคิดข้อมูลหรือเขียนโค้ด
  - ต้องแจกแจงเส้นทางการทำงานของกลุ่มผู้มีส่วนได้ส่วนเสีย (Stakeholder Journey) อย่างชัดเจน

  [กฎข้อที่ 3: ขั้นการย่อยข้อมูลอัจฉริยะ (02_analyzed_data_notebooklm)]
  - ข้อมูลดิบจากขั้นตอนแรกจะต้องถูกสังเคราะห์และย่อยข้อมูลผ่าน NotebookLM (หรือระบบ AI) ก่อนจัดเก็บลงในโฟลเดอร์นี้
  - ห้ามสร้างไฟล์วิเคราะห์โดยไม่มีการอ้างอิงกลับ (References/Citations) ไปยังไฟล์ข้อมูลดิบต้นทาง

  [กฎข้อที่ 4: ขั้นการประเมินและการทำตารางวิเคราะห์ (03_matrices)]
  - ทุกฟีเจอร์ที่จะถูกเลือกไปสร้างใน Prototype จะต้องผ่านการประเมินใน "ตารางการประเมินความคุ้มค่าและผลกระทบ (Feasibility-Impact Matrix)"
  - ต้องจัดทำ "ตารางวิเคราะห์ข้อมูลความต้องการ (Data Requirement Matrix)" และ "ตารางความเสี่ยงและการบริหารจัดการ (Risk & Governance Matrix)" 
    เพื่อระบุปัญหาด้านข้อมูลและความเป็นส่วนตัว (PDPA/HIPAA) ก่อนทำต้นแบบ

  [กฎข้อที่ 5: ขั้นการส่งมอบข้อมูลสู่หน้าจอต้นแบบ (04_production_inputs)]
  - เฉพาะข้อมูลที่ผ่านการตรวจสอบกับเวิร์กโฟลว์และเมทริกซ์ประเมินเรียบร้อยแล้วเท่านั้น จึงจะนำเข้าสู่โฟลเดอร์นี้ได้
  - ข้อมูลที่จัดเก็บในส่วนนี้จะต้องเป็นข้อมูลสะอาด พร้อมใช้สำหรับสร้างต้นแบบ เช่น ไฟล์เคสผู้ป่วยจำลอง (mock_cases.csv), 
    กฎเกณฑ์การประเมินตัดสินใจ (decision_rules.md), และเอกสารข้อกำหนดความต้องการระบบต้นแบบ (prototype_requirements.md)

4. STAKEHOLDERS & ROLES (ผู้มีส่วนร่วมและบทบาทหน้าที่ในระบบ)
--------------------------------------------------------------------------------
  - บุคลากรทางการแพทย์ (Clinicians/Epidemiologists): ตรวจสอบแนวทางการทำงานและกฎเกณฑ์ตัดสินใจ (Decision Rules) 
    เพื่อให้มั่นใจว่าคำแนะนำจากระบบปลอดภัยและใช้การได้จริงในโรงพยาบาล
  - นักพัฒนาและวิศวกรข้อมูล (Data Engineers/Developers): พัฒนาระบบต้นแบบและทดลองป้อนข้อมูล Mock Cases 
    ตามสถาปัตยกรรมที่กำหนดไว้ในขั้นตอนสุดท้าย
  - ผู้บริหารและผู้รับผิดชอบโครงการ (Project Managers/Sponsors): ใช้ตารางวิเคราะห์ (Matrices) ในการประเมินศักยภาพ 
    ควบคุมงบประมาณ ความเสี่ยงด้านกฎหมาย และจัดการทรัพยากรการส่งมอบโครงการ

5. KEY DELIVERABLES & MEASUREMENTS (ผลส่งมอบหลักของโครงการและดัชนีชี้วัด)
--------------------------------------------------------------------------------
ความสำเร็จของเฟสพัฒนาต้นแบบจะวัดจากผลส่งมอบดังต่อไปนี้:
  - เวิร์กโฟลว์แผนภาพสถานะปัจจุบันและสถานะในอนาคต (General Workflow Artifact)
  - แฟ้มตารางประเมินผลกระทบ ความเสี่ยง และความต้องการเชิงข้อมูลที่สมบูรณ์ (Matrices Artifact)
  - ไฟล์โครงสร้างข้อมูลผู้ป่วยและปัจจัยสิ่งแวดล้อมที่สะอาดพร้อมใช้งานจริง (Production Inputs Artifact)
  - แผงควบคุมแสดงผลต้นแบบจำลอง (Interactive Dashboard Prototype UI / Mockup) 
    ซึ่งแสดงวิธีการแจ้งเตือนความเสี่ยงของผู้ป่วยที่ได้รับผลกระทบจากปัจจัยแวดล้อมและอุณหภูมิ
